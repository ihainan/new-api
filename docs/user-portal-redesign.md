# 用户端门户改造方案（v2）

分支 `feat/user-portal-redesign`。目标：普通用户登录后直接看到一个可用的门户，
形态参考 ZGCAI-Coding-Plan 的 portal「已领取」状态，去掉一切申请/领取环节。

**管理员界面不在范围内，一行不改。**

> v1 作废。v1 把管理员侧栏当成了用户界面，前提整个错了；评审指出后已实测纠正，
> 下面第 1 节是以普通用户身份实际登录后看到的真实基线。

---

## 1. 真实基线（实测，非推断）

用 `devuser`（role=1）登录开发环境实拍。这个分叉对普通用户与管理员走的是
**两套完全独立的布局**，`PageLayout.jsx:74` 的 `showSider` 带 `isAdmin()` 条件，
`PageLayout.jsx:149` 直接注释写着「非管理员：独立的精简布局，完全不复用 admin 的 Header/Sider」。

普通用户看到的是 `SimpleHeader`（一个居中的药丸形导航条，fork 自研，非上游），
导航**只有三项**：

| 导航 | 指向 | 现状 |
|---|---|---|
| Models | `/pricing` | 价目表视角 |
| Keys | `/console/token` | **「暂无 Key，请联系管理员分配 API Key」** |
| Dashboard | `/console/dashboard` | 4 张统计卡 + 7 天 Token 折线 + 最近 10 次请求 |

右上角头像菜单只有「退出登录」一项。

**最严重的问题一眼可见**：新用户进去，Keys 页写的是「请联系管理员分配 API Key」。
这就是要消灭的那个「申请」环节——而且它甚至不是一个按钮，是一句让你去找人的话。

（附带发现：这个分叉限制密码登录仅管理员可用，`controller/user.go:65`，
普通用户只能走钉钉。本次不改这条，但它意味着任何用户端验收都要考虑登录方式。）

---

## 2. 目标形态

导航从三项扩到四项，全部在 `SimpleHeader` 内完成，**不碰 `SiderBar`**：

| 导航 | 路由 | 说明 |
|---|---|---|
| 概览 | `/console/dashboard` | 重做内容 |
| API 密钥 | `/console/token` | 自动发放 + 接入示例 |
| 模型 | `/pricing`（沿用） | 改为「我能调什么」视角 |
| 使用记录 | `/console/log` | 新增入口，用户此前没有 |

**路由不新增、不改名**，只改导航呈现与页面内容。`/console/midjourney`、`/console/task`
等旧地址保持可直达。

### 明确不做

- 不显示余额、额度、订阅状态（按你的要求，Coding-Plan 那块整块不搬）。
- 不做任何「申请 / 领取」交互。
- **不改管理员界面**：`SiderBar.jsx` 整个文件不动，`adminItems`、`workspaceItems`
  都不碰（v1 曾误判 `workspaceItems` 是用户的，实际它属于管理员侧栏）。
- 不改 `Log`、`ModelGallery` 等共享页面给管理员用的那条分支。
- 不改计费、鉴权、relay。

## 3. 逐页方案

### 3.1 API 密钥（最优先）

**发放策略（按评审裁决修正）。** v1 打算让自助接口忽略 `GenerateDefaultToken`，
评审判定不可接受——管理员关掉它可能正是不想自动发，静默绕过既不安全也无法解释。

改为两步：

1. **主路径**：确认开启 `GenerateDefaultToken`（生产已经是 `true`），
   并对存量无密钥用户做**一次性回填脚本**。这解决绝大多数情况，不需要页面加载时写数据库。
2. **自愈路径**（可选，需单独决策）：若确实需要长期自愈，新增独立策略开关
   `SelfServiceDefaultTokenEnabled`，默认关闭，作为部署配置，不动管理员 UI。
   接口仅在该开关开启时工作。

若实施自愈接口，幂等必须做到数据库级，不能「先查后建」：

- 给 `tokens` 加 nullable `purpose` 列，默认令牌固定 `purpose='default'`，
  对 `(user_id, purpose)` 建唯一约束；
- 发放与唯一槽位在同一事务内，用 GORM `OnConflict DoNothing` 收敛并发
  （进程内锁不够，可能多实例部署）;
- 发放条件是「**是否曾经发过**」而不是「当前有没有可用令牌」——否则用户删掉密钥
  或额度耗尽后反复调用，会变成「额度补领」。

接口约束（评审补充，全部采纳）：不解析请求体里的 `user_id`（出现即拒绝），
仅用 `c.GetInt("id")`；挂 `CriticalRateLimit()` 与 `DisableCache()`；
响应只回掩码元数据，明文走已有的带归属校验的接口；记审计。

**重新生成**：本期**不提供**。评审指出当前只能删了再建，不是原子轮换，
会出现短暂无密钥或并发覆盖。要做需要单独的 rotate 接口，不在本期范围。

**接入示例**：密钥下方给可复制代码，按协议分标签——OpenAI 兼容（curl / Python SDK）、
Anthropic 兼容（curl / Python SDK）。`base_url` 从 `/api/status` 的 `server_address` 取。

### 3.2 概览

两块内容：

**调用情况**：今日请求、今日 Token、累计 Token。
**质量指标**：平均耗时、缓存输入占比、首字延迟、上游调用失败比例。

下方模型分布表（模型、请求数、占比）。

去掉现有的「最近 10 次请求」（使用记录页会覆盖它）。

**必须新写后端聚合接口**（v1 说「可能需要」，评审核实为「必须」）：

- `/api/data/self` 只返回按小时+模型的原始行，单次最长 30 天，给不出累计值，
  且依赖 `DataExportEnabled`，有约 5 分钟刷新延迟；
- `/api/log/self/stat` 只有 quota / rpm / tpm，而且**按 username 聚合而非 user_id**
  （用户名可变，不稳定）。

因此新增 `GET /api/log/self/metrics`，按 `user_id` 聚合，需在接口契约里定死：

- 时间范围参数、"今日"以 Asia/Shanghai 为界（由后端算边界返回，不靠前端时区）；
- 平均/分位只统计成功的 `type=2`；
- 分位数在 Go 里算，不依赖数据库（SQLite/MySQL/PostgreSQL 无统一 percentile 语法）；
- 空数据、错误日志关闭、明细被清理三种情况返回**「不可用」而不是 0**。

**P95 本期不做**（评审第 3 问）。单用户日调用量常在几十次量级，P95 没有统计意义，
且月报口径里从未定义过 P95。只显示均值并标注样本数。

**口径沿用月报文档但仅限可沿用部分**（`ZGCAI-New-API-Admin/docs/monthly-report-metrics.md`）：

可直接沿用：缓存输入占比、首字延迟（必须同时过滤 `is_stream=1` 且 `frt>0`）、
失败比例（分母 `type IN (2,5)`，客户端断开算成功）。

不可沿用、需本方案另行定义：P95（月报未定义，本期不做）；
错误日志默认关闭时的降级表述；开启重试后需按 `request_id` 归并。

**命名**：「缓存命中率」改为「缓存输入占比」（评审建议，更准确）。

### 3.3 模型

沿用 `/pricing` 路由，改为用户视角：一句话说明「你当前可以调用的模型」，
保留搜索，每个模型加「复制模型 ID」。不显示价格倍率。

### 3.4 使用记录

**不做统一稀疏表格**（评审否决 v1 方案）。三类日志字段差异大：绘图有图片、
提示词、进度；任务有完成时间、平台、结果 URL、音视频预览。

改为：一个页面框架 + 类型分段控件（对话 / 绘图 / 任务），每类渲染自己的表格与详情。
**本期不提供「全部类型」**——跨三个数据源的全局排序与稳定分页需要新的后端聚合，
不值得为此扩大范围。

类型分段控件是否出现，跟随已有的 `enable_drawing`、`enable_task` 配置。

## 4. 实施顺序

1. 存量用户密钥回填脚本（一次性，解决当下最痛的问题）
2. 后端 `GET /api/log/self/metrics`
3. 前端 `SimpleHeader` 扩到四项 + 响应式断点
4. API 密钥页（展示 + 接入示例）
5. 概览页重做
6. 使用记录页（框架 + 三类分段）
7. 模型页调整
8. （可选，需单独决策）自助发放接口 + `purpose` 唯一约束

---

## 5. 管理员零改动的保证

- `SiderBar.jsx`、`HeaderBar`、`adminItems`、`workspaceItems` 全部不改；
- 所有改动集中在 `SimpleHeader.jsx` 与 `!isAdmin()` 分支渲染的组件；
- `/console/log`、`/pricing` 等共享路由按角色分支：管理员继续渲染原组件；
- 新增后端路由挂在 `logRoute` 的 `self` 段与 `tokenRoute` 下，与管理端路由无交集；
- **验收必须包含管理员回归**：以 role=100 登录，逐一访问 `/console`、token、log、
  midjourney、task、model-gallery、personal、topup、channel、user，确认与改造前一致。

## 6. i18n 与移动端（v1 遗漏，评审补充）

- 项目有七个语言：`zh-CN/zh-TW/en/fr/ru/ja/vi`。新文案必须 `t('中文原文')` 并同步全部语言。
- 现有 `SimpleHeader`、`UserDashboard`、`ReadonlyTokensTable` 已有大量硬编码中文，
  本次涉及的部分顺带补齐，不涉及的不动。
- 验收要跑 `bun run i18n:extract`、`i18n:sync`、`i18n:lint`、`build`。
  `i18n:lint` 是独立脚本，`build` 不覆盖它。
- `SimpleHeader.css` 目前**没有任何媒体查询**，导航项固定横向 padding。
  加到四项后窄屏会溢出。验收宽度定为 **320 / 375 / 768 / 1440**。
- 使用记录在窄屏应降级为卡片而非横向滚动表格。

---

## 7. 仍需决策的两点

1. **自助发放接口做不做？** 主路径（开关 + 一次性回填）已能解决当前问题。
   自愈接口要改表结构（加 `purpose` 列与唯一约束），成本明显更高。
   建议本期只做主路径，自愈接口留到确有需要时。
2. **额度耗尽的提示。** 去掉余额显示后，额度用尽时用户将毫无线索。
   建议保留一个仅在耗尽时出现的错误态提示，而非常驻余额数字。
